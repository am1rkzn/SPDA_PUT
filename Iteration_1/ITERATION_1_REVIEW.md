## 3. Решения и расхождения

Демонстрационная аренда с вымышленными велосипедами обязательна для итогового MVP. Платежей, оборудования и интеграций с реальными прокатами нет. Роли пяти участников сохраняются. Предложение коллеги о Flux/pull известно из переписки, но действующая установка Flux или другого CD не доказана.

## 4. Integration Readiness Assessment

**Статус: Frontend готов к предметной сверке и подключению, интегрированный релиз пока не готов к приёмке.** Основание — статический аудит и успешный `npm.cmd run build` на 10.11. Vite 5.4.21 собрал 41 модуль, `npm.cmd ls --depth=0` прошёл без ошибок. В `package.json` есть только `dev/build/preview`, автоматические тесты и lint-команда не найдены. Браузерный прогон с Backend и картой не выполнялся, успешная сборка их не заменяет.

### Что уже есть в интерфейсе

`App.jsx` управляет фильтрами, выбором маршрута, экранами и арендой. `PreferenceForm` передаёт категорию, предел времени 15/30/60 и теги. `Recommendations`/`RouteTile` показывают карточки и пустую выдачу. `MapView` получает геометрию и велосипеды. `BikePicker` выбирает велосипед, `ActiveRental` показывает состояние и завершение, `StatusBanner` отображает ошибки.

`api.js` отделяет интерфейс от источника данных. Только значение `VITE_USE_MOCK=false` включает HTTP, любое другое или отсутствующее значение оставляет mock. В mock используются шесть приблизительных маршрутов, три велосипеда и `localStorage` с ключом `put-rental-demo`. Избранное также локальное и не требует серверного развития для этого релиза.

### Фактические ожидания клиента, не утверждённый контракт Backend

Пути ниже взяты из [api.js](frontend/src/api.js). Они описывают текущего потребителя. Ирина и Егор могут согласовать другой интерфейс и минимально адаптировать клиент.

| Операция | Что отправляет клиент | Что UI ожидает в ответе и что согласовать |
|---|---|---|
| Рекомендации | `GET /api/routes`, параметры `trip_type`, `max_duration`, `tags` через запятую | Массив карточек без обёртки, поля `id`, `title`, `categories` (массив), `durationMin`, `tags`. Фото/рейтинг/отзывы необязательны. Значение `любой` тоже отправляется — определить трактовку. Совпадение тегов и правила порядка выдачи согласовать |
| Выбранный маршрут | `GET /api/routes/{id}` | Объект с полями карточки, `description`, `start`, `geometry.type=LineString` и `geometry.coordinates`. В данных `[долгота, широта]` |
| Велосипеды | `GET /api/bikes` | Массив `id`, `label`, `status`, `coords`. Доступным UI считает только `available` |
| Текущая аренда | `GET /api/rental` | Объект или отсутствие аренды. Клиент принимает JSON `null` либо 204. 404 считается ошибкой. Объект должен давать `routeId`, `bikeId`, `startedAt`, желательны подписи `routeTitle`/`bikeLabel` |
| Начало | `POST /api/rental`, тело `bike_id` и `route_id` | Объект аренды. `selectedRoute.id` реально передаётся. Запрос использует snake_case, UI читает camelCase — автоматического преобразования нет |
| Завершение | `POST /api/rental/finish`, без тела и ID | UI очищает аренду после успеха. Ответ должен быть 204 либо корректным JSON, пустой 200 сломает разбор. Как определяется текущая аренда — вопрос режима пользователя |
| Ошибки и сессия | JSON, дополнительных заголовков идентификации нет | Читается `error.message` и `error.code`, иначе только HTTP-статус. Согласовать 4xx/конфликты/повторы. Общий демопользователь или анонимные сессии ещё не подтверждены, при разных origin отдельно решить cookies/CORS |

### Карта, сборка и размещение

Фактически `MapView` импортирует **Яндекс JS API 2.1** из `map.ymaps21.js`. Этот адаптер преобразует координаты в широта/долгота. Без `VITE_YANDEX_API_KEY` предусмотрена ошибка. `map.js` с MapLibre/OpenFreeMap и `map.yandex.js` для API 3.0 присутствуют, но не используются. Их наличие не подтверждает проверку альтернатив. Комментарий «карта по умолчанию» в `map.js` устарел.

Сборка создаёт статический `dist`. `VITE_USE_MOCK`, адрес API и ключ карты подставляются при сборке, простое изменение env уже запущенного Pod их не заменит. Клиентский ключ карты виден в браузере и требует ограничений для согласованного домена. [Документация Vite](https://vite.dev/guide/env-and-mode).

Прокси `vite.config.js` существует для dev-сервера и ведёт `/api` на `localhost:8000` без удаления префикса. Production-маршрутизация не представлена. Предложение для сверки с существующими решениями Ирины и Амира — один origin, статика из Backend либо уже предусмотренного web-сервера, `/api` к Backend. Запуск Vite dev/preview не планируется как способ production-размещения. Имена сервисов, порт, команда запуска, путь БД, readiness-проверка, registry и манифесты должны поступить от владельцев.
